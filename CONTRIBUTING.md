# Contributing

Thank you for considering a contribution!

## Before You Start

- Read the [README](README.md) to understand the project and how to run it.
- Check existing issues and pull requests before starting substantial work.
- For large changes, open an issue first to discuss the proposed approach.
- By submitting a contribution, you agree that your contribution is provided under the repository's AGPL-3.0-or-later license, to the extent you have the right to do so. You retain copyright in your contributions unless you separately agree otherwise.

## How to Contribute

1. Fork the repository.
2. Create a focused branch from the default branch.
3. Make your changes, following the existing conventions.
4. Add or update tests and documentation where appropriate.
5. Run the project's tests, linting, and other checks.
6. Commit your changes with a clear message.
7. Open a pull request and explain the problem, the solution, and any relevant testing.

## Pull Request Checklist

- [ ] The change has a clear purpose and scope.
- [ ] Tests have been added or updated where appropriate.
- [ ] Documentation has been updated where needed.
- [ ] No credentials, API keys, personal data, or other secrets are included.
- [ ] The relevant checks pass, or any failures are explained.
- [ ] The pull request describes any breaking changes.

## Code Style

Follow the conventions already used in the relevant part of the codebase. Keep changes focused and avoid unrelated refactoring.

## Issues and Feature Requests

Use the repository's issue tracker. Include clear reproduction steps for bugs, expected and actual behavior, relevant logs, and environment details. Remove secrets and personal information from logs before sharing.
