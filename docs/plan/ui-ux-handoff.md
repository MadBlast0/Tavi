# Dockable workspace UI handoff

## What is in place

The workspace is rendered in the app's existing content region by `WorkspaceHost` and `WorkspaceLayout`. A Code Session pane title bar carries compact Terminal, Changes, Browser, and Files buttons with an icon-only overflow for secondary views; there is no additional workspace toolbar. Starting a new session clears the focused pane binding before resetting the real composer, keeping that pane in place. `PANE_TYPES` supplies names and icons; `PANE_REGISTRY` maps each type to its renderer and actions. `Pane` is the shared flat pane frame, and `LayoutTree` draws the pane/split/tab tree.

The docking engine is app-owned code, with no docking package. `src/lib/workspace-state.ts` owns pane instances, pane references, the split/group tree, active pane, six-pane limit and validated versioned serialization. Layout geometry and pane references persist locally. Session history remains in the existing conversation repository; prompt drafts and pane-local sample input/content are not part of the layout serialization. Pane-local sample state is carried through the native pop-out/dock-back event but is not persisted between app runs.

The workspace supports split and tab docking, pane drag/drop, sidebar session drag/drop, a keyboard-accessible sidebar action to open/focus sessions beside the active pane, a compact Code Session title bar for Terminal, Changes, Browser, Files and overflow views, divider resizing by pointer and keyboard, focus, maximize/restore, close and persisted restore. Keyboard-only rearrangement of an already-open pane remains outstanding after removal of the global Move view control. The separate view-count/Layout/Move/Add toolbar has been removed after comparison with Claude Desktop. Chat and Code session panes mount the existing `PromptBlock` with isolated composer-side providers and the real conversation ID. Tool panes use local sample state with visible prototype labeling.

## Reference behavior

Anthropic's [Desktop documentation](https://code.claude.com/docs/en/desktop#arrange-your-workspace) describes pane headers, pane types, drag/rearrange, resizing, pop-out and dock-back. Its [parallel sessions documentation](https://code.claude.com/docs/en/desktop#work-in-parallel-with-sessions) describes opening a second session side-by-side with a modifier-click or context-menu action. The user-confirmed sidebar-drag workflow is recorded in `ui-ux-research.md`; it is implemented as a Tavi affordance and is not presented as an Anthropic-documented shortcut.

## Boundaries and remaining integrations

- Browser and Application Preview are contained local examples; neither navigates arbitrary URLs nor starts a local server.
- Terminal records sample input locally and never executes it.
- File Explorer, File Editor and File Preview use sample content; they do not browse, read or write the selected project.
- Diff Viewer, Logs, Tasks, Plan and Agent Activity show labeled examples; there is no Git diff, process logging, task runner, plan service or agent execution behind them.
- A native popped-out pane keeps its pane identity and local sample state and can dock back to its prior position or a selected target/edge. New windows stay hidden until the pane webview has registered its close/dock listener; creation waits for both the child readiness event and the main window's close hook, then reveals the window, and destroys/reports a window that never becomes ready. Pop-out requests are serialized per pane so repeated activation cannot treat an initializing hidden window as ready. Dock-back carries a request ID and state snapshot, and the pane window closes only after the main window acknowledges restoration. Desktop panes, tabs and sidebar sessions use CrabNebula `drag-as-window` with Tauri native drag-over positions for cross-window drop previews; accepted pane drops are acknowledged before the source window closes. The browser keeps HTML DnD. The implementation compiles; a native close request during a reply queues dock-back until the source webview reports idle. Command-driven Windows UI verification confirmed pop-out creation, the in-window Dock back action, and native close-request dock-back. That check found and fixed the main window's missing core:window:allow-show permission. The persistent plugin Channel callback was replaced with a Tauri native DragDrop listener and a Rust reader restricted to the plugin-prefixed temporary payload file, so child windows can remain drop targets without the teardown panic. Pointer-driven drag preview/drop and live stream synchronization are still unverified. Stale persisted pop-out markers are checked against actual native windows at startup.
- Each Tauri webview has its own in-memory conversation runtime. Pop-out is refused while the same session is replying in the main window. A throttled Tauri event snapshot mirrors live turns/status/tool activity to sibling webviews, with source filtering and per-source revision checks; docking back reloads the durable stored turns (including attachment content) into the main runtime. Command-driven native tests confirmed the window handoff path; live conversation streaming across WebViews remains unverified.
- The pane consistency pass has a width-aware shared header: maximize/pop-out controls move into the existing menu at very narrow widths; Chat/Code state controls wrap; Code activity has its own scroll region. Tauri event ordering and live synchronization have app-level revision/source handling; they still need native verification.
- Screenshot references are not checked into the repository, and this pass did not use mouse-driven visual QA. The automated checks cover source contracts and the workspace's state/interaction rules, not pixel comparison.

## Verification

`pnpm typecheck`, `pnpm build` and `pnpm test` pass; the final full-suite checkpoint reports 428 passing tests. The dock-back request helper has runtime tests for matching acknowledgements, refusal, timeout and listener cleanup. `cargo check --manifest-path src-tauri/Cargo.toml` passes, and `pnpm tauri dev` compiles and starts the native app. Physical pointer drag through accepted native drop, provider-generated cross-window streaming, assistive-technology review and pixel comparison against a Claude Desktop screenshot remain outstanding. A command-driven native event probe verified snapshot synchronization, but it is not evidence of provider-generated streaming.
